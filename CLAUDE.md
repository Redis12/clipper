# Clipper : CLAUDE.md

> **Nouvelle conversation ? Lire d'abord `REPRISE.md`** (travail en cours, programmation, règles de l'utilisateur), puis `DEJA_FAITES.md` avant de proposer une vidéo.

## But
Deux produits dans le même outil :
1. **Slideshows** (priorité actuelle) : niche anime, en anglais. Claude propose des sujets, écrit les slides, choisit les images de la bibliothèque (vision), l'outil rend des carrousels 9:16 / 4:5 et un Short vidéo, puis publie sur YouTube (auto), Instagram et TikTok (auto si configurés, sinon packs à poster à la main).
2. **Clips** : coller une URL YouTube (vidéo, playlist ou chaîne) et obtenir 5 à 15 clips candidats de 2 à 5 min par vidéo, chacun avec une note sur 100, 3 titres, une description, 10 tags et une miniature. On valide en un clic dans une page locale, et les clips validés partent dans une file de publication programmée sur YouTube (upload **toujours en privé** avec `publishAt`).

Tout tourne en local (v1, aucun cloud à part les API appelées).

## Stack
- Python ≥ 3.11, SQLite (WAL) pour l'état, fichiers sous `data/`
- yt-dlp (téléchargement, demande un runtime JS : Deno ou Node), ffmpeg/ffprobe
- Deepgram nova-3 (`language=fr`, diarisation), WhisperX en option (`transcription.engine: whisperx`)
- API Anthropic via **sorties structurées** (`output_config.format` json_schema, `llm.structured`) : `tool_choice` forcé est refusé par les modèles récents. `llm.api_schema` ajoute `additionalProperties: false` et retire min/max.
- OpenCV (netteté, visages Haar) + Pillow pour les miniatures
- FastAPI + Jinja2 + JS vanilla pour la revue
- YouTube Data API v3 (OAuth installed app) pour l'upload

## Pipeline (`clipper/pipeline.py`)
Chaque étape est **idempotente** : elle lit l'état SQLite, saute ce qui est fait et écrit ses sorties dans `data/videos/<id>/`.

1. `ingest.py` : yt-dlp en meilleure qualité, `info.json` et métadonnées en base, puis proxy 480p H.264 pour le navigateur.
2. `transcribe.py` : audio mono 16 kHz Opus, Deepgram, puis `transcript.json` normalisé `{words:[{w,s,e,spk}]}`. Jamais refait si le fichier existe.
3. `selection.py` : phrases numérotées (`transcript.py`), puis Claude, qui rend des **index de phrases**. Les longues transcriptions passent en blocs qui se recouvrent, puis fusion (chevauchement < 20 %).
4. `bounds.py` : bornes aux frontières de phrase, marge 0,3 s sans mordre sur le mot voisin, durée de 120 à 300 s sinon `rejected_auto` avec la raison.
5. `titles.py` : 3 titres de 60 car. max, description, 10 tags, texte de miniature de 3 à 4 mots.
6. `cut.py` : découpe précise à la frame (ré-encodage), 1080p max en 16:9, loudnorm en 2 passes à −14 LUFS, fondus audio de 0,3 s.
7. `thumbs.py` : 10 frames, sélection netteté et visage, texte posé avec Pillow, JPEG 1280×720 de moins de 2 Mo.
8. `web/` : revue, raccourcis clavier, ajustement de ±1 s (marque `render_needed`).
9. `schedule.py` + `youtube.py` + `quota.py` : créneaux, upload reprenable étape par étape, quota par seau, blocage sans perte de file.

## Slideshows (`clipper/slides/`)
- `ideas.py` : idées (`generate_ideas`), sujet perso (`add_user_topic`), script (`write_script`, 2e essai si règles non tenues).
- `library.py` : `library/<Anime>/<Personnage>/*.jpg`, `library/<Anime>/_frames/<source>/` (captures), `library/_music/`. Index en table `images` ; `pick()` montre ≤12 candidates à Claude (vision). ≥4 images rangées pour le perso → on ne montre que celles-là. Évite les images utilisées depuis moins de `avoid_reuse_days`.
- Téléphone : `web/lan.py` (clé dans `data/lan_key.txt`, requise hors 127.0.0.1, puis cookie) ; page `/m` pour enregistrer les images et copier la légende, puis poster avec un son depuis l'app. Ouverte sur le PC, `/m` affiche le lien téléphone + QR code (`qrcode`, SVG) et prévient si le serveur n'a pas `--lan` (`CLIPPER_LAN`). Sans clé, le téléphone reçoit une page avec un champ pour coller la clé (jamais la clé elle-même).
- Emojis sur les slides : `render.draw_rich` découpe le texte et dessine les emojis avec une police couleur (Segoe UI Emoji / Apple / Noto) ; sans police emoji, l'emoji est omis (jamais de carré).
- Tri des captures (`library.tag_frames`, auto après chaque capture si `frames.auto_tag`) : Claude vision par paquets de 12, déplace l'image vers `library/<Anime>/<Perso>/` si confiance ≥ `tag_min_confidence`, sinon `tagged=1` et elle reste en divers. Réutilise l'orthographe des dossiers existants.
- Formats « jeux » (`assign`, `zodiac` : 12 slides fixes ; `redflags`, `as_people`, `opinions`, `wallpaper` sans texte) : `prompts.FIXED_SLIDES` et `prompts.NO_FACTS`. Instagram > 10 images → pack en 2 posts.
- Marque : `slides.render.watermark` (petit, semi-transparent, à 74 % de la hauteur en 9:16 pour rester au-dessus de la légende TikTok, en bas en 4:5, aussi sur la grille) et `slides.render.end_cta` (ligne jaune ajoutée sous le texte de la dernière slide ; le prompt interdit à Claude d'écrire lui-même un « follow »). Chaîne vide = désactivé. Style `watermark_style: badge` : pilule à notre DA (`render.make_badge`, partie `watermark_highlight` en jaune) générée UNE fois dans `library/_brand/watermark.png` puis réutilisée ; remplaçable par un PNG perso (supprimer le fichier = regénération).
- Format `ratings` (notes d'épisodes) : `ideas.parse_chart` lit les notes dans les consignes (« EP1 8.1 … overall 8.6 IMDb », jamais inventées par Claude ; sans notes → erreur claire), les met dans `slides[0].chart` ; `render.draw_chart` dessine titre + note globale + barres (zone `chart_geometry`, au-dessus de la légende TikTok en 9:16). Exclu des idées automatiques. Logo optionnel : PNG transparent par anime dans `library/_brand/logos/<anime>.png` (envoyé une fois depuis « Mon propre sujet »), affiché à la place du titre si la case est cochée (`slideshows.use_logo`, migration 6). Un PNG déposé à la main dans `library/logos/` est trouvé s'il contient les mots de l'anime (dossier ignoré par le scan). Plusieurs saisons (`ideas.parse_charts`, « S1: … S2: … ») : graphique S1 sur la couverture + une slide graphique par saison suivante (logo sur la dernière), puis top 5 des épisodes toutes saisons. Note globale non fournie → « Avg. IMDb episode rating » (moyenne, pas la note officielle). Une seule note (un épisode ou la note de la série, « IMDb rating 8.3 ») → le post = la carte seule (« EPISODE N · IMDb » ou « IMDb rating » + grosse note + jauge sur 10), sans slides de contenu ni slide de fin.
- Format `news` (actu) : carte unique, titre = le sujet tel quel (`|` = retour à la ligne, `*mots*` en jaune), « — NEWS — » au-dessus, `news_sub` + ▼ dessous, badge en haut à droite (`render.draw_news`). `SUB: …` dans les consignes remplace le sous-titre de la 1re carte (« → » final = flèche dessinée), `//` = retour à la ligne dans un titre ; si toutes les lignes sont « titre — date », rendu en liste (titre à gauche, date à droite, filets entre les lignes). Lignes de consignes « > TAG | titre | sous-titre » = cartes en plus (fun fact…) ; Claude ne fait que choisir le perso de chaque carte et écrire la légende (jamais de date ou détail inventé). Exclu des idées automatiques.
- `upscale.py` : petite image (< `upscale.min_side`) agrandie par Real-ESRGAN anime (`realesrgan-ncnn-vulkan` ou `upscayl-bin`, cherché dans `upscale.bin`, `tools/realesrgan/`, le PATH) à l'ajout, ou toutes avec `clipper upscale` ; original gardé dans `library/_originals/` ; sans moteur, rien ne change (avertissement).
- Format `wallpaper` : images prises dans `library/wallpaper/<Anime>/` (origin `wallpaper`, jamais utilisées par les autres formats ; sinon images normales), sans vision Claude, les moins utilisées d'abord. Couverture = le sujet tel quel en texte simple (« JJK wallpapers >>> »). Chaque wallpaper donne 2 slides : aperçu écran de verrouillage (`render.draw_lock_carousel` : fond noir, téléphone aux coins arrondis avec date + heure en « verre liquide » style iOS 26 (`draw_lockscreen` : chiffres translucides floutant l'image, liseré clair ; étirés en hauteur jusqu'au sujet quand il y a du vide, mesuré par `free_height` sur la densité de contours), points de pagination sous le téléphone, wallpapers voisins qui dépassent à gauche/droite pour inciter à swiper ; `lock`) puis le wallpaper seul (`twin`, même image ; changer l'un change l'autre). « no lockscreen » dans les consignes = pas d'aperçu. Nombre = wallpapers dispo − 1 (couverture), max 6. Filigrane uniquement sur la couverture (ce ne sont pas nos dessins).
- `battle.py` (page Battle, `clipper battle "Gojo,Sukuna,…"`) : vidéo 9:16 « Which anime character wins? ». Persos-balles (avatar rond pris dans leur dossier, la plus nette) dans une arène ronde ; chacun relié au bord par `links_per` liens ; une balle qui touche le lien d'un autre le lui vole ; plus de liens = balle plus grosse ; chaque rebond accélère un peu (`accel`, plafond `max_speed_x`) ; sans lien = éliminé. Règle unique, visible : toucher un trait (au-delà du bord de son perso) = ce lien passe chez toi, l'autre le perd. Icônes de taille fixe. Le lien volé prend tout de suite la couleur du voleur (plus épais un instant) + petit éclat sur le trait touché. Chaque rebond accélère (`accel`), voler aussi (`steal_boost`), plafond `max_speed_x`. Pas de minuteur affiché. Avec cette seule règle les derniers s'échangent leurs liens à l'infini (vérifié en simulation, une vingtaine de variantes) ; on fait donc comme les vidéos virales : montage avec « CUT » (flash blanc). 3+ persos sans élimination depuis `stall_seconds` → CUT, le plus faible sort (ses liens au leader). Les 2 derniers (« FINAL DUEL ») s'échangent leurs liens `duel_seconds` (±3 s), puis CUT → le gagnant = celui qui a le plus de liens à cet instant, il rafle tout. Écran WINNER 3 s + `end_cta` (« Follow … »). Son « pop » synthétisé à chaque vol. Rendu Pillow (fond en cache, lueur en 1/4) → ffmpeg H.264. **Visuels « satisfaisants » (02/11)** : avatars recadrés sur la tête (`faces.head_square`) ; accroche = les persos apparaissent un par un en « pop » (`back_out`) avec éclat + « WHO WINS? » + « Comment your pick 👇 » ; `BattleFX` (moteur du Domain War) : vol de lien = étincelles + éclat star_08 + anneau, le lien claque en blanc puis prend la couleur ; élimination = explosion (pack `explosion_dome` sinon `vfxgen`), onde, débris, onde de choc (`ripple`), punch caméra + secousse, arrêt sur image avec 2 impact frames ; traînées lumineuses ; arène néon à la couleur du leader ; leader = halo pulsé + couronne dorée ; « FINAL DUEL » qui pulse ; écran WINNER = rayons qui tournent, avatar en pop, confettis, « Who should fight next? Comment 👇 » + end_cta. Son (`soundtrack`) : une note de marimba par vol, les vols rapprochés (< 0,45 s) montent la gamme pentatonique (combo), élimination = coup + explosion (banque `_sfx` via `domain.sfx`, franchise du combat), gong de victoire ; l'audio suit les arrêts/coupes (`pauses`, `vt`). Fichiers dans `data/battles/` (+ .json), téléchargeables depuis la page Téléphone.
- `fusion.py` (page Fusion, `clipper fusion`) : vidéo 9:16 « Fusion Battle » façon Suika Game. Idée de l'utilisateur ; recherche faite (nov. 2026) : aucun outil existant ne fait images perso + sons perso + export vidéo (jeux Suika, appli Bubble Merge sans export, BallEngine sans fusion). Chaîne de 3 à 10 niveaux (idéal 6–8, au-delà ~2 min) : soit persos de la bibliothèque cliqués dans l'ordre (champ caché `order`), soit dossier `library/_fusion/<nom>/` (images triées par nom naturel, « 1 Base.png » → niveau « Base » ; ou fichier `ordre.txt` dans le dossier : une ligne par niveau « fichier = Nom affiché », prioritaire, pour ne pas renommer les images — on ne peut pas renommer/supprimer sur le PC à distance). Icônes TOUJOURS recadrées en carré sur la tête (`faces.py`, demandé par l'utilisateur, une seule tête par image) : vision Claude = boîte du visage (fractions), mémorisée dans `data/faces.json` (clé chemin+date+taille), carré = 1,9 × le visage, centré un peu au-dessus (cheveux) ; sans clé : lbpcascade_animeface (`clipper/assets/`, MIT — rate souvent le style Dragon Ball, testé) puis Haar, puis heuristique (haut de la silhouette). `vision_faces: false` pour couper. PNG sans fond : tête posée sur un disque coloré. Deux modes (`style`) : `bounce` (défaut, demandé par l'utilisateur) = gravité légère, chocs élastiques, chaque icône garde sa vitesse (`speed` × R/s, les gros niveaux un peu moins vite) → elles rebondissent partout dans le bol ; `pile` = tas au fond façon Suika. Tube droit au-dessus du bol (comme les vidéos virales), halo coloré derrière chaque icône, néon arc-en-ciel. Icônes qui tombent du tube (animation scriptée `DROP_TIME`, l'icône « en attente » est celle qui tombe), puis physique (gravité, chocs à positions corrigées, paroi ronde) ; 2 icônes du même niveau qui se touchent → niveau suivant au milieu, petit « pop » + anneau. Rayons géométriques de 0,10R (0,08R si > 8 niveaux) à 0,40R. **Démarrage** (`fast_start`, demandé avec capture d'une vidéo virale : les gens partaient après 2 s) : une **colonne** d'icônes de base espacées de 2,3 r, du haut du tube jusqu'au fond du bol, qui tombe à la même vitesse (`Feeder.tube` = celles encore dans le tube, dessinées par `draw_dynamic(tube=)`) ; la première rebondit au fond → fusions en bas, la colonne s'effondre de bas en haut (1re fusion ~0,2 s, SSJ3 ~1,5–4 s). Puis lâchers normaux, plus rapides (`drop_every` 0,55 s, min 0,26 s). Le tube ne lâche jamais une forme pas encore apparue (`spawn_tier` plafonné à `best`). Néon **arc-en-ciel** (vert en haut à gauche → jaune → orange → rose en bas → violet → bleu → cyan en haut à droite ; tube vert à gauche, cyan à droite), la Fusion Race garde ses couleurs d'équipe. Lâchers : surtout les petits niveaux (jusqu'à top//2, max 4), priorité aux niveaux qui ont un partenaire seul ; rythme `drop_gap` adapté au nombre de niveaux. Anti-blocage invisible : attraction entre jumeaux proches (`sim.pull`) qui monte si rien ne fusionne depuis 4 s ou si le bol est plein (pas de lâcher au-delà de 60 % de remplissage) ; forte après `max_seconds`. Vérifié en simulation : niveau final toujours atteint (4 niv. ~16 s, 6 ~30 s, 8 ~50 s, 9 ~65 s, 10 ~110 s). PAS d'échelle/aperçu des niveaux (retiré à la demande de l'utilisateur : le suspense « c'est quoi la forme suivante ? » fait rester les gens). Fin : 1 s, puis écran « FINAL FORM » + `end_cta` (emoji via draw_rich). Son : bruitage choisi dans `library/_sounds/` (envoi depuis la page, 15 Mo max) ou « bloop » synthétisé ; par fusion, `tier_sound` le rejoue plus lent/grave (≤ 3 demi-tons par niveau, ~2 octaves au total), basses ajoutées (passe-bas FFT, pas de scipy), saturation tanh et écho qui s'allongent ; réglage « Gras » 0–2 (`fat`). **Plusieurs sons** (04/11, « varie les sons ») : `generate(sound=[…])` (ou « a|b|c ») = une liste du plus léger au plus lourd, chaque niveau prend le sien (`tier * len // tiers`), toujours rejoué plus grave ; DBZ : ki blast → coup → aura burst → téléportation → aura SSJ → explosion (pack Dragon Ball SFX). **Durée ≥ 30 s** (04/11, règle de l'utilisateur) : `generate(opts={"drop_every": 0.8–1.4, "drop_every_min": 0.4–0.9}, seed=…)` ralentit les lâchers ; graine choisie en simulant sans rendu. **Musique de fond** : `generate(music=…, music_gain=)` = jouée une fois en continu (bouclée si courte), pas par fusion (thème de Perfect Cell rejoué à chaque fusion = « décalage du fou »). Niveau général `slides.fusion.volume` (défaut 0,13 ≈ −24 LUFS, 03/11 : l'utilisateur trouvait le son « bcp trop fort » à −6 LUFS). Bouton « Écouter » = `/fusion/preview.wav` (le son à chaque niveau). Fichiers `data/fusions/` (+ .json), aussi sur la page Téléphone. **Easter egg** (idée de l'utilisateur, « un Zoro qui s'est perdu ») : ligne `fichier = Nom | easter` dans ordre.txt (ou `generate(easter=…)`) → ce n'est pas un niveau ; quand l'avant-dernière forme apparaît, le perso arrive par la droite SOUS le bol, regarde à gauche/droite avec des « ? », bulle « Where am I? 🗺️ » à sa gauche, puis repart dans le mauvais sens (6 s, `_easter_overlay`) ; la vidéo attend la fin du gag.
- `powerup.py` (« Power Up », `generate(chain, boss, hero_name, boss_name)`) : idée de l'utilisateur inspirée d'une vidéo virale « Can Fibonacci pay off the US National Debt in under 60 seconds? » (analysée image par image : compte à rebours dans le titre, croissance exponentielle, un seul événement répété + nombre qui flotte + son, fin pile à 0 s, 62 s). - `domain.py` + `movesets.py` (page Battle, section « Domain War », `clipper domain "A,B"`) : idée retenue par l'utilisateur, inspirée de Pong Wars (rien trouvé en version anime). Grille 26 colonnes (13,5 %→78 % de la hauteur), moitié à la couleur de chaque perso ; 3 balles (visage) par camp traversent leur domaine et repeignent + rebondissent sur les cases adverses. **Fiches de persos** (demandé par l'utilisateur : attaques fidèles au perso, pas au hasard) : `library/_domain/<Perso>.txt` (`movesets.PRESETS`, 52 persos dont toute la bibliothèque JJK, écrits au 1er usage, jamais écrasés ; perso inconnu → Claude écrit la fiche une fois, sinon générique). ## Statuts d'un clip
`pending` → `review` → `approved` (avec `publish_at`) → `uploaded`
Sorties de route : `rejected_auto` (bornes, repêchable dans la revue), `rejected` (toi).
Une erreur d'upload remplit `error` mais garde le clip `approved` : il est repris au prochain `publish`. Si `youtube_id` est déjà renseigné, seules les étapes manquantes (miniature, playlist) sont refaites.

- **Règle permanente de l'utilisateur (18/11) : plus JAMAIS de format « Guess »** (Snake « Guess the character », « Find the Joestar », Guess the fused characters, devinettes en général) : ~2k vues sur TikTok, ne plus en proposer ni en programmer.
- **Règle permanente (05/11) : filigrane sur CHAQUE vidéo, tous formats** (« faut pas qu'on se fasse voler nos vues ») : anime = `render.stamp_video` (badge @ANIMELOREHQ) à la fin de tout nouveau format (Hydraulic Press, intros, montages…) ; Money Sim = son propre badge `tools/money_sim/badge_moneysim.png` via `tools/money_sim/stamp.py` (positions hors texte : sous le titre / bas de la boîte). Vérifier une image avant livraison.
- **Règle permanente de l'utilisateur (02/11) : « optimise toujours la première seconde »** : à chaque nouveau format ou changement d'accroche, vérifier l'image 0 (persos visibles, sujet lisible sans contexte, jamais un écran vide) et l'action dans la 1re seconde.
- Pas de module nommé comme la stdlib (d'où `selection.py`, pas `select.py`).
- Tous les temps sont en **secondes float** dans le code et la base. Le formatage `hh:mm:ss` n'existe qu'à l'affichage.
- Dates en base en **UTC ISO 8601**. Les créneaux de publication s'expriment dans `publish.timezone` (Europe/Brussels). Le quota YouTube se compte en **jour Pacific**.
- Aucune clé dans le code ni dans `config.yaml` : uniquement `.env`.
- La publication n'écrit **jamais** `privacyStatus: public`. Une assertion dans `youtube.py` le garantit.
- Chaque appel API YouTube est journalisé dans `quota_log` **avant** d'être retenté.
- Les prompts Claude sont dans `clipper/prompts.py`, en français.
- Modifier le schéma = ajouter une migration dans `db.MIGRATIONS` (jamais éditer une migration existante).
- Tenir ce fichier à jour à chaque changement de commande, de config ou de convention.

## Décisions prises (et pourquoi)
- Claude choisit des **index de phrases**, pas des timecodes : ça garantit des bornes propres et évite les horodatages inventés.
- Le proxy 480p sert la revue : lecture instantanée et ajustement de ±1 s sans re-rendu. Le clip final n'est re-rendu qu'au besoin (`render_needed`) avant l'upload.
- Haar cascade (livrée avec OpenCV) plutôt que mediapipe : aucune dépendance de plus, et suffisant pour dire s'il y a un visage.
- Quota : YouTube compte `videos.insert` dans un seau séparé (100 appels/jour). Les miniatures et playlists (50 + 50) puisent dans les 10 000 unités. Les coûts sont dans `config.yaml` → `quota`.
- Pas d'upscale : une source sous 1080p garde sa hauteur native, mise en 16:9 par pad.
- `opencv-python-headless<5` : OpenCV 5 ne livre plus les cascades Haar. Sans cascade, la miniature retombe sur la netteté seule (avertissement dans le journal).
- Marge de 0,3 s plafonnée au milieu du silence voisin : on n'entend jamais le bout du mot d'avant ou d'après.
- Un rendu terminé pendant qu'on ajustait les bornes reste marqué `render_needed`.
- Un seul fil de travail dans `clipper serve` (ffmpeg occupe déjà tous les cœurs). Les titres d'une même vidéo partent en parallèle (4 appels Claude).
- Deux files de travail dans `clipper serve` (`web/jobs.py`) : `video` (ffmpeg lourd) et `slides`, pour qu'une longue vidéo ne bloque pas les slideshows. Désactivées quand `CLIPPER_TESTING` est défini.
- Verrous `.lock` : contiennent le PID ; un verrou laissé par un processus mort est ignoré (`util.pid_alive`, sans `os.kill` sous Windows).
- Téléchargements plafonnés à 1080p (`ingest.format`).
- Raccourcis clavier compatibles AZERTY (a/z/q/s pour les bornes, &/é/" pour les titres).
